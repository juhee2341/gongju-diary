# 화면 기획

22개 화면을 모두 같은 틀로 정리한다. 용어, 상수(대문자 이름), 감정·리액션 키, 알림 타입은 spec.md '요구사항'의 정의를 따른다.

화면마다 다음 순서로 쓴다.

- **진입**: 이 화면에 오는 경로
- **배치**: 위에서 아래 순서의 구성 요소
- **상태**: 데이터·권한에 따라 달라지는 표시
- **동작**: 사용자 행동과 결과
- **엣지 케이스**: 예외 상황과 처리 (공통 규칙에 있는 것은 반복하지 않음)
- **데이터**: 읽고 쓰는 테이블과 서버 함수

## 공통 규칙

모든 화면에 적용하며, 화면별 엣지 케이스에서는 반복하지 않는다.

### 내비게이션

- 하단 탭 3개: 홈(B1) · 알림(F1, 안 읽은 수 배지 99+, 앱 아이콘 배지도 같은 수) · 설정(G1). A1\~A4, D1, E3, G4 계정 삭제에서는 하단 탭을 숨긴다
- 화면 이동은 스택. 일기장 안(C1\~C4, D1, D2, E1\~E3)은 홈 탭 스택에 쌓인다
- 푸시 탭 진입: 해당 탭의 루트 화면을 깔고 그 위에 대상 화면을 연다. 앱 잠금이 켜져 있으면 A2를 먼저 통과한다
- 딥링크: `gongju://join/{코드}`와 `https://{도메인}/j/{코드}` → B3(코드 자동 입력)
- 안드로이드 뒤로가기는 상단 바 뒤로와 같게 동작, 루트 화면에서는 두 번 눌러 종료

### 네트워크·로딩

- 첫 로딩: 화면 모양의 스켈레톤. 이미 캐시가 있으면 캐시를 먼저 보여주고 뒤에서 갱신
- 목록 화면은 당겨서 새로고침, 앱이 포그라운드로 돌아오면 현재 화면 자동 갱신. 앱 사용 중 푸시를 받으면 관련 화면 데이터를 갱신하고 상단 인앱 배너(3초, 탭하면 이동)로 보여준다. 실시간 구독은 쓰지 않는다
- 오프라인: 상단 띠 배너 "인터넷 연결이 없어요". 읽기는 캐시, 쓰기 버튼은 회색으로 두고 탭하면 같은 문구 토스트
- 요청이 REQUEST\_TIMEOUT(10초)을 넘거나 실패: 토스트 "잠시 후 다시 시도해 주세요" + 화면에 다시 시도 버튼. 서버가 일시정지에서 깨어나는 경우도 같은 처리
- 저장·삭제 버튼은 요청 중 비활성 + 버튼 안 로딩 표시(연타로 중복 요청 방지)
- 이미지는 디스크 캐시 사용. 목록에는 썸네일, 원본은 D2와 전체화면에서만

### 권한·세션

- 익명 세션은 앱 실행마다 자동 갱신. 갱신 실패 시 A1의 오류 상태로
- 서버가 "멤버 아님"을 돌려주면(내보내짐, 일기장 삭제): 토스트 "사라진 일기장이에요" → B1로 스택 초기화
- 서버가 "일기 없음"을 돌려주면(작성자 삭제·탈퇴): 토스트 "삭제된 일기예요" → 이전 화면
- 내 역할이 바뀐 경우(위임받음): 다음 화면 진입이나 갱신 때 주인 전용 요소 노출
- 차단 관계인 사람의 일기·댓글·리액션·알림은 모든 목록에서 숨기고 숫자 집계에서도 뺀다. 차단당한 쪽에는 아무것도 알리지 않는다

### 입력

- 글자 수는 사용자가 보는 글자 단위(grapheme)로 센다. 이모지·한글 조합 문자 모두 1자
- 저장 전 앞뒤 공백 제거, 공백·줄바꿈만 있으면 빈 값
- 본문 줄바꿈은 최대 연속 2줄로 정리
- 제한 글자 수에 닿으면 더 입력되지 않고, 붙여넣기가 넘치면 잘라 넣은 뒤 토스트 "{N}자까지 쓸 수 있어요"
- 입력 중인 화면에서 뒤로가기·닫기: 변경 내용이 있을 때만 확인창 "작성 중인 내용이 사라져요" (나가기 / 계속 쓰기)
- 키보드가 입력창과 하단 버튼을 가리지 않도록 화면을 밀어 올린다

### 날짜·시간

- 오늘은 기기 현지 날짜. 화면을 켜둔 채 자정을 넘기면 포그라운드 복귀 시 또는 1분 주기로 다시 계산하고, 오늘에 의존하는 표시(작성 여부, 쓰기 버튼, 잠김·자동 공개)를 갱신
- 날짜 표기: 목록은 "11월 19일 (목)", 연도가 다르면 "2025년 11월 19일 (수)". 시간은 1시간 안이면 "N분 전", 오늘이면 "오후 3:20", 그 외 "11월 18일"
- 사용자가 기기 시간을 바꾸면 서버 날짜 검증(spec.md 데이터 구조)에 걸려 저장이 거부될 수 있다: 토스트 "기기 날짜를 확인해 주세요"

### 문구

- 존댓말 "\~해요" 체. 특정인은 "{닉네임}님", 다수는 "공주들"
- 확인창은 제목 1줄 + 설명 1\~2줄 + 버튼 2개(오른쪽이 실행). 삭제·나가기처럼 되돌릴 수 없는 실행 버튼은 danger
- 토스트는 화면 하단, 2.5초 표시, 동시에 1개
- 사라진 사용자는 "떠난 공주" + 흐린 왕관 기본 아바타

### 접근성

- primary 위 글자와 본문 모두 명도 대비 4.5:1 이상
- 시스템 글꼴 크기 확대 시 레이아웃이 깨지지 않도록 고정 높이 대신 최소 높이 사용
- 감정·리액션·잠김 아이콘에는 스크린리더 라벨(감정 라벨, "잠긴 일기")
- 터치 영역 최소 44×44pt

### 알림 권한 요청

- 온보딩에서는 묻지 않는다. 처음으로 ① 함께 쓰기 일기장을 만들거나 ② 참여 요청을 보내거나 ③ 함께 쓰기 일기장에 첫 일기를 저장한 직후 한 번만 묻는다
- 순서: 앱 바텀시트 "친구가 일기를 쓰거나 댓글을 남기면 알려드릴까요?"(좋아요 / 나중에) → 좋아요일 때만 시스템 팝업
- "나중에"를 고르면 7일 뒤 같은 조건에서 한 번 더 묻고, 그 뒤로는 G3에서만 켤 수 있다
- 물어본 기록은 기기에 저장한다

### 화면 모드

- G1에서 시스템 / 라이트 / 다크 선택(기본 시스템), 기기에 저장
- 모든 색은 spec.md '디자인 방향'의 라이트·다크 토큰만 사용

### 햅틱

- 감정 선택, 리액션, 일기 열림 애니메이션, PIN 입력 오류에 가벼운 진동

## A. 시작

### A1 스플래시

**진입**: 앱 실행(콜드 스타트), 푸시 탭으로 실행, 딥링크로 실행.

**배치**

1. primary 배경 전체
2. 중앙 왕관 로고 + "공주일기"
3. 하단 로딩 점 3개

**상태**

- 기본: 로고 + 로딩
- 오류: 로고 아래 오류 문구 + "다시 시도" 버튼
- 강제 업데이트: "새 버전이 나왔어요" + "업데이트하기"(스토어 이동), 다른 진행 불가

**동작**

1. app\_config.min\_version 확인 → 현재 버전이 낮으면 강제 업데이트 상태
2. 저장된 세션 확인 → 없으면 익명 계정 생성
3. user\_settings.timezone, push\_tokens, profiles.last\_seen\_at 갱신(백그라운드, 포그라운드 복귀 때도)
4. 앱 잠금 켜짐 → A2
5. 온보딩 미완료(기기 기록 없음) → A3, 프로필 없음 → A4, 그 외 → B1
6. 푸시·딥링크로 실행했다면 5의 화면 위에 대상 화면을 연다(공통 규칙 내비게이션)

**엣지 케이스**

- 첫 실행인데 오프라인: 익명 계정을 만들 수 없음 → 오류 상태 "처음 시작할 땐 인터넷이 필요해요"
- 세션은 있는데 오프라인: 캐시로 B1 진입 + 오프라인 배너
- 익명 계정 생성 3회 연속 실패: 오류 문구 아래 "문의하기" 링크
- 재설치(계정 미연결): 새 익명 계정이 생겨 이전 일기장을 볼 수 없다. A3 마지막 장의 "이전 계정 불러오기"로만 복구 가능(계정 연결한 경우)
- 버전 확인 실패: 강제 업데이트 검사만 건너뛰고 진행. 계정이 정지 상태(profiles.status = suspended)면 "이용이 제한된 계정이에요" + 문의하기만 표시하고 진행 불가
- 프로필 만들기 도중 앱 종료 후 재실행: 온보딩 완료 기록이 있으므로 A4부터

**데이터**: app\_config, profiles, user\_settings, push\_tokens.

### A2 잠금 화면

**진입**: A1(잠금 켜짐), 백그라운드에서 LOCK\_DELAY 이상 지난 뒤 복귀.

**배치**

1. 상단 왕관 로고
2. 안내 문구 "비밀번호를 입력해 주세요"
3. 하트 4칸(입력 수만큼 채워짐)
4. 숫자 키패드 3×4 (빈칸 / 0 / 지우기)
5. 하단 텍스트 버튼 "비밀번호를 잊었어요"

**상태**

- 입력 대기
- 틀림: 하트가 좌우로 흔들리고 비워짐, 문구 "비밀번호가 달라요 (N/5)"
- 대기 중: 키패드 비활성, 문구 "{남은 초}초 후에 다시 입력할 수 있어요"

**동작**

- 4자리 입력 즉시 검증 → 맞으면 잠기기 전 화면(또는 푸시 대상 화면)으로
- PIN\_FAIL\_LIMIT: 5회 틀릴 때마다 대기(30초 → 60초 → 120초 … 최대 10분), 맞히면 실패 횟수 초기화
- "잊었어요" → 계정 연결 사용자: 바텀시트 "연결한 계정으로 확인하면 잠금을 풀 수 있어요" → 구글/애플 재인증 → 성공 시 잠금 해제 + G2 PIN 재설정 화면

**엣지 케이스**

- 계정 미연결 사용자의 "잊었어요": 바텀시트 "계정을 연결하지 않아 비밀번호를 찾을 수 없어요. 앱을 지우면 일기도 함께 사라져요" + 닫기만
- 재인증에서 연결된 계정과 다른 계정 선택: 토스트 "연결된 계정과 달라요", 잠금 유지
- 대기 중 앱 종료 후 재실행: 실패 횟수와 대기 종료 시각을 secure storage에 저장해 이어서 적용
- 기기 시계를 앞으로 돌려 대기 회피: 대기 시간은 기기 부팅 후 경과 시간으로 계산하고, 재부팅으로 경과 시간이 초기화되면 남은 대기를 처음부터 다시 적용
- 잠금 중 도착한 푸시: 미리보기는 "새 소식이 있어요"
- 생체 인증은 쓰지 않음(요구사항: 비밀번호만)

**데이터**: 기기 secure storage(PIN 해시, 실패 횟수, 대기 종료 시각). 서버 없음.

### A3 온보딩

**진입**: A1(온보딩 완료 기록 없음). 최초 1회.

**배치**

1. 우상단 "건너뛰기"
2. 가로 스와이프 카드 3장: ① "하루 한 편, 짧게 써요"(사진 3장, 300자) ② "내가 써야 친구 일기가 열려요"(잠긴 카드 그림) ③ "혼자도, 친구랑도 쓸 수 있어요"(일기장 카드 그림)
3. 점 인디케이터
4. 하단 버튼: 1\~2장 "다음", 3장 "시작하기"
5. 3장 아래 텍스트 버튼 "이전 계정 불러오기"

**상태**: 장 번호에 따라 버튼 문구만 바뀜.

**동작**

- "시작하기" → 약관 동의 바텀시트(전체 동의 / \[필수\] 만 14세 이상이에요 / \[필수\] 이용약관 / \[필수\] 개인정보 수집·이용, 항목마다 "보기") → 필수 항목을 모두 체크하면 "동의하고 시작" 활성 → 온보딩 완료 기록 → A4. "건너뛰기"는 3장으로 이동(동의 단계는 건너뛸 수 없음)
- "이전 계정 불러오기" → 구글/애플 로그인 → 연결된 계정이 있으면 그 계정으로 전환하고 B1(프로필이 이미 있으므로 A4 생략). 없으면 토스트 "연결된 계정이 없어요"

**엣지 케이스**

- 만 14세 항목을 체크하지 않음: 진행 불가, 안내 "공주일기는 만 14세 이상부터 쓸 수 있어요"
- 약관 개정: A1에서 profiles.terms\_version이 최신과 다르면 다른 화면보다 먼저 재동의 바텀시트를 띄움
- 이전 계정 불러오기 시 지금 기기의 새 익명 계정: 데이터가 없으므로 경고 없이 버림

**데이터**: 기기 저장소(온보딩 완료, 동의 버전·시각 — A4 완료 때 profiles로 저장), 인증.

### A4 프로필 만들기

**진입**: A1·A3(프로필 없음). 수정 모드는 G1의 프로필 편집.

**배치**

1. 상단 제목 "나를 소개해 주세요"(수정 모드: "프로필 고치기" + 뒤로)
2. 원형 아바타 미리보기(지름 120)
3. 토글 "이모지 / 사진"
4. 이모지 선택 시: 이모지 그리드 4×6(공주 테마 24종). 사진 선택 시: "사진 고르기" 버튼
5. 닉네임 입력 + 우측 "0/10"
6. 하단 "완료" 버튼

**상태**

- 완료 버튼: 닉네임 1자 이상일 때 활성
- 업로드 중: 아바타 위 원형 진행 표시

**동작**

- 사진 고르기 → 갤러리 → 정사각 크롭 → AVATAR\_SIZE로 압축 → 완료 시 업로드
- 완료 → profiles(약관 동의 포함)·user\_settings 생성 + 혼자 쓰기 일기장 "나의 공주일기"(cover\_1) 자동 생성 → B1. 수정 모드는 갱신 후 이전 화면

**엣지 케이스**

- 닉네임 중복: 허용. 같은 일기장에 같은 닉네임이 있으면 아바타로 구분
- 금지어 포함: 입력창 아래 danger 문구 "사용할 수 없는 단어가 있어요", 완료 비활성
- 사진 권한 거부: 토글을 이모지로 되돌리고 토스트 "사진 접근을 허용하면 사진을 쓸 수 있어요" + 설정 이동
- 사진 업로드 실패: 이모지 기본값(👑)으로 저장하고 토스트 "사진은 설정에서 다시 바꿀 수 있어요"
- 아무것도 고르지 않음: 👑 이모지
- 수정 모드에서 닉네임 변경: 이미 쓴 일기·댓글의 표시도 새 닉네임으로 바뀜(알림은 snapshot이라 예전 이름 유지)

**데이터**: profiles, user\_settings, avatars 버킷.

## B. 홈과 참여

### B1 홈 (내 일기장 목록)

**진입**: A1·A4 완료, 하단 탭 홈, 나가기·삭제 완료 후, "사라진 일기장" 처리 후.

**배치**

1. 상단: "안녕, {닉네임}님" + 오늘 날짜 "11월 19일 (목)" + 우측 아바타(탭 → G1)
2. 계정 미연결이고 일기를 3편 이상 썼으면 primarySoft 안내 카드 "계정을 연결하면 기기를 바꿔도 일기가 남아요" + 연결하기 / 닫기(닫으면 30일간 숨김)
3. 대기 요청이 있으면 띠 "승인 기다리는 중 {N}개" (탭 → B4)
4. 일기장 카드 목록: 고정한 일기장 먼저, 그 다음 last\_activity\_at 최신순
5. 카드 구성: 커버 색상 띠, 이름, 주인이면 왕관, 멤버 아바타 최대 4개 + "+N", 오늘 작성 리본("오늘 썼어요" / "아직이에요"), 함께 쓰기면 "오늘 {N}명 썼어요", 주인이고 대기 요청이 있으면 알림 점 + "요청 {N}"
6. 하단 고정 버튼 2개: "일기장 만들기"(primary) / "초대 코드로 참여"(테두리)

**상태**

- 빈 상태(일기장 0개): 왕관 일러스트 + "첫 일기장을 만들어 볼까요?", 하단 버튼 유지
- 일기장 20개 이상: 상단에 검색 아이콘(이름 검색). 함께 쓰기 일기장이 하나도 없으면 목록 아래에 카드 "친구와 함께 쓰면 더 재밌어요" + 만들기 / 참여하기

**동작**

- 카드 탭 → C1
- 카드 길게 누르기 → 바텀시트: 상단에 고정 / 고정 해제, 일기장 설정(E1)
- 리본 "아직이에요" 탭 → D1(오늘 날짜)

**엣지 케이스**

- 자정이 지나면 모든 리본이 "아직이에요"로 바뀐다(공통 날짜 규칙)
- 혼자 쓰기 일기장: 멤버 아바타와 "오늘 N명" 대신 최근 감정 아이콘 7개
- 내보내짐·일기장 삭제: 다음 갱신 때 카드가 사라짐. 사유는 F1 알림으로만 알림
- 위임받음: 카드에 왕관이 붙음
- 고정한 일기장이 여러 개: 고정끼리 last\_activity\_at 순
- 차단한 멤버는 아바타 묶음과 작성 수에서 제외

**데이터**: diary\_members(+pinned), diaries, entries(오늘 날짜 집계), join\_requests(내 대기, 주인일 때 받은 요청 수).

### B2 일기장 만들기

**진입**: B1 "일기장 만들기".

**배치**

1. 상단 바: 닫기 + "새 일기장"
2. 커버 미리보기 카드(선택한 색 + 입력한 이름)
3. 이름 입력 + "0/20"
4. 커버 색상 8개 원형 칩(COVER\_COLORS)
5. 쓰기 방식 카드 2개: "혼자 쓰기" / "함께 쓰기"
6. 함께 쓰기 선택 시에만: "늦게 쓰기 허용" 세그먼트 1일 / 3일 / 7일(기본 3일) + 설명 "이 기간이 지나면 안 쓴 사람도 일기를 볼 수 있어요"
7. 하단 "만들기"

**상태**: 만들기 버튼은 이름 1자 이상 + 쓰기 방식 선택 시 활성. 기본 색상은 cover\_1.

**동작**

- 만들기 → create\_diary → 혼자 쓰기면 C1, 함께 쓰기면 초대 공유 바텀시트(코드 크게, "코드 복사", "공유하기", "나중에") → C1 → 처음이면 공통 규칙의 알림 권한 요청
- 공유하기: 시스템 공유 시트, 문구 "공주일기에서 같이 일기 써요! 초대 코드 {코드} {링크}"

**엣지 케이스**

- 같은 이름의 일기장: 허용. 금지어는 닉네임과 같은 목록으로 검사(banned\_word), E1 이름 수정도 같음
- 초대 코드 충돌: 서버에서 다시 생성해 돌려줌(사용자는 모름)
- 혼자 쓰기: late\_window\_days 7 고정, invite\_code 없음
- 만들기 중 실패: 토스트 + 입력 유지

**데이터**: create\_diary → diaries, diary\_members(owner, joined\_date = 오늘).

### B3 초대 코드로 참여

**진입**: B1 "초대 코드로 참여", 딥링크(코드 자동 입력).

**배치**

1. 상단 바: 닫기 + "일기장 참여하기"
2. 안내 "친구에게 받은 6자리 코드를 입력해 주세요"
3. 6칸 코드 입력(대문자 자동 변환, 붙여넣기 시 6칸 자동 분배)
4. "찾기" 버튼
5. 찾은 뒤: 일기장 미리보기 카드(커버 색, 이름, 주인 닉네임·아바타, "멤버 {N}/10") + "참여 요청 보내기"

**상태**

- 입력 중 / 찾는 중 / 찾음(미리보기) / 오류(입력칸 아래 danger 문구)
- 실패 제한: CODE\_FAIL\_LIMIT 도달 시 입력 비활성 + "{남은 초}초 후에 다시 시도해 주세요"

**동작**

- 찾기 → request\_join 사전 조회 → 미리보기
- 참여 요청 보내기 → join\_requests(pending) 생성 → join\_requested 알림 → B4로 교체 이동 → 처음이면 공통 규칙의 알림 권한 요청

**엣지 케이스** (오류 문구)

- 없는 코드, 재발급으로 바뀐 옛 코드, 혼자 쓰기 일기장, 차단 관계인 주인의 일기장: 모두 같은 문구 "코드를 다시 확인해 주세요"(차단 사실 노출 금지) + 실패 횟수 1 증가
- 이미 멤버: "이미 함께하고 있어요" + "일기장으로 가기"(→ C1)
- 이미 대기 중: "승인을 기다리고 있어요" + "요청 취소"
- 인원 가득 참: "자리가 꽉 찼어요", 요청 버튼 없음
- REJECT\_COOLDOWN 이내: "조금 뒤에 다시 요청할 수 있어요"
- 이전에 나갔거나 내보내진 일기장: 정상 요청 가능(주인 화면에 표시됨)
- 딥링크로 들어왔는데 앱이 첫 실행: A1\~A4를 마친 뒤 B3로 이어서 열고 코드 자동 입력

**데이터**: request\_join → diaries(조회), join\_requests, member\_history(표시용).

### B4 참여 대기

**진입**: B1 대기 띠, B3 요청 완료, join\_rejected 알림.

**배치**

1. 상단 바: 뒤로 + "참여 요청"
2. 요청 목록: 커버 색 점, 일기장 이름, "{M월 D일} 요청", 상태 칩(대기 중 / 거절됨 / 만료됨), 대기 중이면 "취소"

**상태**

- 빈 상태: "보낸 요청이 없어요"
- 거절됨·만료됨: REJECT\_DISPLAY(7일) 동안 표시 후 숨김

**동작**

- 취소 → 확인창 "요청을 취소할까요?" → status cancelled → 목록에서 제거
- 승인되면 목록에서 사라지고 B1에 카드가 생김(join\_approved 푸시)

**엣지 케이스**

- 취소와 승인이 동시에: 서버에서 먼저 처리된 쪽이 적용. 이미 승인됐으면 토스트 "이미 승인되었어요" → C1
- 대기 중 일기장 삭제 또는 REQUEST\_EXPIRE 경과: 만료됨
- 대기 중 인원 가득 참: 대기 유지(주인이 자리를 만들면 승인 가능)
- 거절 사유는 표시하지 않음

**데이터**: join\_requests(내 요청).

## C. 보관

C1\~C3은 한 화면 안의 세그먼트 탭(주 / 월 / 년)이고, 마지막으로 본 탭을 일기장별로 기억한다. 모든 보관 화면에서 이동 가능한 범위는 일기장 created\_date가 있는 주·월·년부터 오늘이 있는 주·월·년까지다.

### C1 일기장 메인 (주간)

**진입**: B1 카드, join\_approved·member\_left 알림, D1 저장 후 뒤로.

**배치**

1. 상단 바: 뒤로, 커버 색 점 + 일기장 이름, 멤버 아바타 묶음(탭 → E2), 설정 아이콘(→ E1)
2. 세그먼트 탭: 주 / 월 / 년
3. 주 선택 바: "11.17 \~ 11.23" + 좌우 화살표, 오늘이 있는 주가 아니면 우측에 "오늘" 버튼
4. 날짜 행 7개(week\_start 기준 시작): 왼쪽에 "17 월", 오른쪽에 멤버 아바타 가로 나열, 아바타 아래 상태 아이콘
5. 하단 고정 버튼(오늘 상태에 따라 문구 변경)

**상태**

- 아바타 상태 아이콘(열람자 기준): 작성+열림 = 감정 아이콘 / 작성+잠김 = 자물쇠 / 미작성 = 점선 원 / 참여 전 날짜 = 아바타 표시 안 함
- 날짜 행: 오늘 = primary 테두리, 작성 가능한 지난 날짜 중 내가 안 쓴 날 = "아직 쓸 수 있어요" 배지, 미래 = 흐리게(탭 불가)
- 하단 버튼: 오늘 안 씀 = "오늘 일기 쓰기" / 오늘 씀 = "오늘 일기 보기"(→ C4 오늘)

**동작**

- 날짜 행 탭 → C4(그 날짜)
- 좌우 스와이프 또는 화살표로 주 이동
- 하단 버튼 → D1(오늘) 또는 C4(오늘)

**엣지 케이스**

- 멤버 6명 이상: 아바타 5개 + "+N", 전체는 C4에서
- 아바타 순서: 나 → 주인 → 나머지 참여일 순(모든 화면 공통)
- 혼자 쓰기: 아바타 대신 감정 아이콘 + 본문 첫 줄 미리보기(1줄 말줄임)
- 한 주가 두 달에 걸쳐도 날짜 범위로만 표시
- 생성일이 있는 주보다 이전, 오늘이 있는 주보다 이후: 화살표 비활성
- 오늘 썼다가 삭제: 버튼이 "오늘 일기 쓰기"로 돌아가지만 열림은 유지(남의 일기 계속 보임)
- 차단 관계인 멤버: 아바타 표시 안 함

**데이터**: entries(주 범위, 작성자·날짜·감정만), entry\_unlocks(나), diary\_members.

### C2 월간 캘린더

**진입**: C1 세그먼트 "월", C3 미니 달력 탭.

**배치**

1. 상단 바(C1과 같음), 세그먼트 탭
2. 월 선택 바: "2026년 11월" + 좌우 화살표 + "오늘"
3. 요일 헤더(week\_start 기준)
4. 달력 그리드(필요한 주 수만큼 5\~6줄)
5. 날짜 칸: 숫자, 내 감정 아이콘(크게), 우하단 작은 숫자 "{작성한 멤버 수}"
6. 그리드 아래 "이번 달 내 감정" 가로 막대(감정별 횟수, 많은 순, 0회 감정은 숨김)

**상태**

- 내가 쓴 날: 내 감정 아이콘
- 내가 안 썼고 작성 가능: 점선 원
- 내가 안 썼고 자동 공개됨: 흐린 점
- 오늘: primary 원 배경 / 미래·생성일 이전: 흐리게, 탭 불가
- 데이터 없는 달: 그리드 아래 "이 달은 조용했어요"

**동작**: 날짜 탭 → C4, 좌우 스와이프로 월 이동.

**엣지 케이스**

- 잠긴 일기의 감정은 숫자 집계에만 반영되고 아이콘으로는 드러나지 않음
- 혼자 쓰기: 우하단 숫자 없음
- 내가 참여하기 전 날짜: 숫자만 표시, 탭하면 C4에서 모두 열린 상태로 보임(열람 규칙 4)

**데이터**: entries(월 범위, 날짜·작성자·감정), entry\_unlocks(나).

### C3 연간 보기

**진입**: C1 세그먼트 "년".

**배치**

1. 상단 바, 세그먼트 탭
2. 연도 선택 바 "2026년" + 좌우 화살표
3. 요약 "올해 쓴 일기 {N}편 · 가장 많았던 감정 {아이콘 라벨} · 최장 연속 {N}일"
4. 미니 달력 12개(3열 × 4행), 각 달 제목 "11월", 날짜 칸은 내가 쓴 날만 그날 감정 색 점(spec.md '감정 색상')

**상태**: 생성일 이전 달·미래 달은 흐리게, 탭 불가. 일기 0편이면 요약 대신 "올해 첫 일기를 기다리고 있어요".

**동작**: 미니 달력 탭 → 그 달의 C2.

**엣지 케이스**

- 생성 연도 이전, 올해 이후로 이동 불가
- 성능: 연간 조회는 내 일기의 날짜·감정만 가져온다. 최장 연속은 이 일기장에서 내가 쓴 날짜가 끊김 없이 이어진 가장 긴 구간(늦은 일기 포함, 빠진 날을 나중에 채우면 이어짐)

**데이터**: entries(내 것, 연 범위).

### C4 하루 모아보기

**진입**: C1 날짜 행, C2 날짜 칸, C1 하단 "오늘 일기 보기", D1 저장 완료, entry\_created 알림(잠김일 때).

**배치**

1. 상단 바: 뒤로 + "11월 19일 (목)" + 좌우 화살표(전날/다음 날)
2. 내가 안 썼고 작성 가능하면: 상단 배너 "이날 일기를 쓰면 모두의 일기가 열려요" + "쓰기" 버튼
3. 내 일기 카드(썼을 때)
4. 멤버 일기 카드 목록(아바타 순서 규칙)
5. 맨 아래 "아직 안 쓴 공주들" + 아바타 줄(참여 전 멤버 제외)

**상태** (카드)

- 열린 카드: 아바타·닉네임, 감정 아이콘·라벨, 배지(늦은 일기 / 수정됨), 사진 썸네일 최대 3개, 본문 3줄 말줄임, 하단 리액션 수·댓글 수
- 잠긴 카드: 아바타·닉네임 + 흐린 종이 배경 + 자물쇠 리본 + "내 일기 쓰면 열려요" (감정·사진 수·글 길이·반응 수는 숨김)
- 저장 직후 진입: 잠긴 카드들이 차례로 열리는 애니메이션 + 토스트 "오늘 일기가 열렸어요"

**동작**

- 열린 카드 탭 → D2
- 잠긴 카드 탭 → 바텀시트 "이날 일기를 쓰면 바로 볼 수 있어요" + 쓰기(→ D1 그 날짜). 작성 기간이 지났으면 이 경우는 생기지 않음(자동 공개)
- 좌우 화살표·스와이프로 날짜 이동(미래, 생성일 이전 불가)

**엣지 케이스**

- 자동 공개된 날(나는 안 씀): 모든 카드 열림, 배너 대신 textSub 안내 "이날은 내 기록이 없어요"
- 작성 기간이 끝나는 자정을 넘기며 보고 있음: 날짜 재계산 시 다시 조회해 열린 상태로 갱신
- 아무도 안 쓴 날: "이날은 모두 쉬었어요"
- 혼자 쓰기: 내 카드만, "아직 안 쓴 공주들" 없음
- 내가 참여하기 전 날짜: 모든 카드 열림, 쓰기 배너 없음
- 멤버가 그 날짜 일기를 삭제: 카드 사라지고 "아직 안 쓴 공주들"로 이동

**데이터**: entries(그 날짜, can\_view\_entry 통과분만 본문·사진), 잠긴 일기는 작성자 id만, entry\_unlocks, reactions·comments 수.

## D. 일기

### D1 일기 작성/수정

**진입**: C1 하단 "오늘 일기 쓰기", C4 쓰기 배너·잠긴 카드 바텀시트, B1 리본 "아직이에요", reminder 푸시(일기장이 1개면 그 일기장, 여러 개면 B1), D2 더보기 "수정".

**배치**

1. 상단 바: 닫기(X) + 날짜 칩 "11월 19일 (목) · 오늘" + 우측 "저장"
2. 날짜가 오늘이 아니면 칩 아래 안내 "늦은 일기로 표시돼요"
3. "오늘 기분은?" + 감정 10종 가로 스크롤(아이콘 + 라벨, 선택 시 primarySoft 배경)
4. 사진 칸 3개(정사각): 빈 칸은 "+", 채운 칸은 썸네일 + 우상단 X, 길게 눌러 순서 바꾸기
5. 본문 입력: 편지지 줄무늬 배경, placeholder는 오늘의 질문(DAILY\_PROMPTS, 예: "오늘 가장 웃겼던 순간은?") + 질문 옆 새로고침 아이콘으로 다른 질문 보기, 우하단 "0/300"

**상태**

- 저장 버튼: 감정 선택 + (사진 1장 이상 또는 본문 ENTRY\_MIN\_CHARS(5자) 이상)일 때 활성. 사진 없이 1\~4자면 글자 수가 danger + 안내 "5자 이상 써 주세요"
- 수정 모드: 제목 "일기 고치기", 날짜 칩 비활성(날짜 변경 불가), 기존 값 채움
- 저장 중: 전체 화면 반투명 덮개 + "사진 올리는 중 {n}/{전체}" → "저장하는 중"
- 임시저장 복원: 진입 시 같은 일기장·같은 날짜의 임시저장이 있으면 확인창 "쓰던 일기가 있어요" (새로 쓰기 / 이어서 쓰기)

**동작**

- 날짜 칩 탭(작성 모드만) → 바텀시트 달력: 작성 가능 날짜만 선택 가능, 이미 쓴 날짜는 체크 표시 + 비활성
- 사진 +: 갤러리 다중 선택(남은 칸 수만큼 제한) 또는 카메라
- DRAFT\_INTERVAL마다 기기에 임시저장(일기장 id + 날짜 단위)
- 저장 순서: ① entry id 생성(수정 모드는 기존 id) ② 사진을 PHOTO\_SIZE 원본 + THUMB\_SIZE 썸네일로 변환(EXIF 위치 정보 제거) ③ entry-photos에 업로드 ④ save\_entry(날짜 검증, 저장, 열림 기록) ⑤ 임시저장 삭제 ⑥ C4(그 날짜)로 교체 이동 ⑦ 함께 쓰기 일기장 첫 저장이면 공통 규칙의 알림 권한 요청
- 수정 저장 시: edited = true, 빠진 사진 파일은 저장 성공 후 삭제

**엣지 케이스**

- 300자 초과 붙여넣기: 공통 입력 규칙대로 잘라 넣고 토스트
- 사진 형식: HEIC·PNG·WebP는 JPEG로 변환. 50MP급 큰 사진, 극단 비율 스크린샷도 긴 변 기준으로 축소, 썸네일은 중앙 크롭. GIF·동영상은 선택 불가
- 사진 권한 "일부만 허용"(iOS): 허용된 사진만 보이고 상단에 "사진 더 허용하기" 링크
- 사진 권한 거부: + 탭 시 토스트 + 설정 이동, 본문만으로 저장 가능
- 업로드 중 실패: 실패한 사진에 danger 느낌표 + "다시 시도" / "빼고 저장". 일기 저장(④)은 모든 사진 업로드 성공 후에만 실행
- 업로드 후 저장 전 앱 종료: 올라간 사진은 ORPHAN\_CLEANUP으로 삭제, 기기 임시저장은 남음
- 화면을 연 채 자정 경과: 칩 날짜 그대로 저장되고 is\_late = true. 그 날짜가 작성 가능 범위를 벗어나면 저장 시 "쓸 수 있는 기간이 지났어요", 임시저장 유지
- 같은 날짜를 다른 기기에서 먼저 저장: 서버 유니크 제약 오류 → 확인창 "이미 이날 일기가 있어요" (닫기 / 그 일기 고치기)
- 저장 시점에 멤버가 아님(내보내짐·삭제): 확인창 "이 일기장에 더 이상 쓸 수 없어요" + "글 복사하기"(본문을 클립보드로)
- 수정 중 다른 기기에서 그 일기를 삭제: 저장 시 "삭제된 일기예요", 새로 쓸지 묻기
- 본문에 금지어 검사는 하지 않음(신고로 대응)
- 혼자 쓰기: 날짜 칩 범위 7일, 저장 후 C4 애니메이션 없음

**데이터**: save\_entry → entries, entry\_unlocks. entry-photos 버킷. 기기 임시저장.

### D2 일기 상세

**진입**: C4 열린 카드, entry\_created·comment\_created·reaction\_created 알림.

**배치**

1. 상단 바: 뒤로, 작성자 아바타·닉네임, "11월 19일 (목)", 더보기 ⋯. 바로 아래 같은 날 열린 일기의 작성자 아바타 줄(지금 보는 사람 강조, 혼자 쓰기는 숨김)
2. 사진 영역(사진이 있을 때): 가로 슬라이드 + 점 인디케이터, 비율은 정사각 프레임 안에 맞춤
3. 감정 아이콘 + 라벨, 배지(늦은 일기 / 수정됨)
4. 본문 전체(줄바꿈 유지, 링크 자동 인식 안 함)
5. 리액션 바: 6종 버튼, 각 개수(0이면 숫자 숨김), 내가 누른 것은 primary 테두리
6. 댓글 "댓글 {N}" + 목록(아바타, 닉네임, 내용, 시간), 오래된 순
7. 하단 고정 댓글 입력 + "0/100" + 보내기

**상태**

- 댓글 0개: "첫 댓글을 남겨 보세요"
- 사진 로딩 실패: locked 색 칸 + 다시 불러오기 아이콘

**동작**

- 아바타 줄 탭 또는 사진 영역 밖 좌우 스와이프 → 같은 날 다른 열린 일기로 이동(아바타 순서 규칙). 사진 탭 → 전체화면 보기(핀치 줌, 좌우 넘기기, 아래로 밀어 닫기)
- 더보기 ⋯: 내 일기 = 수정(→ D1) / 삭제. 남의 일기 = 신고 / {닉네임}님 차단
- 삭제: 확인창 "일기를 지울까요? 사진과 댓글, 반응도 함께 사라져요" → 삭제 → C4. 열림은 유지
- 리액션: 안 누른 상태에서 탭 = 추가, 다른 리액션 탭 = 교체, 같은 리액션 탭 = 취소. 숫자 길게 누르기 → 바텀시트(리액션별 누른 사람 목록)
- 댓글 보내기 → comments 생성 → 목록 맨 아래 추가 + 스크롤. COMMENT\_RATE를 넘기면 토스트 "조금 천천히 남겨 주세요"
- 댓글 길게 누르기: 내 댓글 = 삭제(확인창), 남의 댓글 = 신고 / 차단. 내 일기에 달린 남의 댓글도 일기 작성자가 삭제 가능
- 신고 → 바텀시트 사유(욕설·괴롭힘 abuse / 불쾌한 사진 photo / 스팸 spam / 기타 etc + 메모) → reports 생성 → 신고한 사람 화면에서 그 일기·댓글 즉시 숨김 → 토스트 "신고가 접수되었어요. 이 글은 더 이상 보이지 않아요" (일기 신고면 이전 화면으로)
- 차단 → 확인창 "{닉네임}님을 차단할까요? 서로의 일기와 댓글이 보이지 않아요. 같은 일기장에는 계속 남아 있어요" → blocks 생성 → 이전 화면

**엣지 케이스**

- 잠긴 일기에 알림·링크로 직접 진입: 서버가 본문을 주지 않음 → C4로 대체 이동(잠긴 카드 상태)
- 보는 중 작성자가 일기 삭제·탈퇴: 다음 동작 시 공통 "삭제된 일기예요"
- 댓글 많음: 최근 COMMENT\_PAGE(20)개 먼저, 맨 위 "이전 댓글 보기"로 20개씩
- 같은 대상 중복 신고: 토스트 "이미 신고했어요"
- 내 일기에 내가 리액션: 허용(알림은 만들지 않음)
- 자기 자신 차단·신고: 메뉴 없음
- 사진 기기 저장: 전체화면에서 길게 누르기 → 저장. 남의 사진 저장 허용 여부는 열어둔 결정 사항(기본 허용)
- 키보드가 올라오면 댓글 입력창이 키보드 위에 붙음

**데이터**: entries(can\_view\_entry), entry-photos, reactions, comments, reports, blocks.

## E. 일기장 관리

### E1 일기장 설정

**진입**: C1 설정 아이콘, B1 카드 길게 누르기, owner\_transferred 알림.

**배치**

1. 상단 바: 뒤로 + "일기장 설정"
2. 커버 미리보기 카드(색 + 이름). 주인에게만 "편집" 버튼
3. 정보 행: 쓰기 방식(혼자 / 함께), 만든 날 "2026년 11월 19일", 주인 닉네임
4. 함께 쓰기일 때: "늦게 쓰기 허용" 1일 / 3일 / 7일 (주인만 변경, 멤버는 읽기 전용)
5. 함께 쓰기일 때: 초대 코드 카드(코드 크게, "복사", "공유하기", 주인만 "새 코드 만들기")
6. "멤버 {N}/10" 행 → E2 (주인이고 대기 요청이 있으면 알림 점)
7. 혼자 쓰기이고 주인일 때: "함께 쓰기로 바꾸기"
8. "이 일기장 알림 받기" 스위치(diary\_members.muted 반대 값)
9. 맨 아래 danger 글씨 "일기장 나가기" → E3

**상태**: 주인 / 멤버에 따라 편집 요소 노출이 다름. 위임받으면 다음 진입 때 주인 화면.

**동작**

- 편집 → 바텀시트(이름 입력 DIARY\_NAME\_LEN, 색상 8종) → 저장
- 늦게 쓰기 기간 변경 → 확인창 → late\_window\_days 저장. 지난 날짜 판정에도 바로 적용
- 새 코드 만들기 → 확인창 "지금 코드는 더 이상 쓸 수 없어요" → 새 코드. 대기 중인 요청은 그대로 유지
- 함께 쓰기로 바꾸기 → 기간 선택(기본 3일) → is\_shared = true, 초대 코드 생성 → 공유 바텀시트

**엣지 케이스**

- 기간을 줄임(예: 7일 → 1일): 확인창 "지난 며칠의 일기가 바로 모두에게 공개돼요". 그 날짜들의 임시저장은 저장할 수 없게 됨
- 기간을 늘림: 이미 자동 공개된 날짜가 다시 잠기는 것은 허용하지 않는다 → 늘리기 전 자동 공개였던 날짜는 entry\_unlocks를 멤버 전원에게 만들어 열린 상태를 유지
- 함께 쓰기를 혼자 쓰기로: 지원하지 않음(멤버가 주인 혼자여도 함께 쓰기 유지)
- 이름을 두 기기에서 동시에 수정: 마지막 저장이 적용
- 멤버가 이 화면을 보는 중 내보내짐: 다음 동작 시 공통 "사라진 일기장이에요"

**주인 맡기 요청** (주인 장기 미접속)

- 노출 조건: 함께 쓰기 일기장, 보는 사람이 멤버, 주인의 last\_seen\_at이 OWNER\_INACTIVE(60일)를 넘음, 대기 중인 요청 없음 → 7번 아래에 "주인 맡기 요청" 버튼과 안내 "주인이 오랫동안 접속하지 않았어요"
- 요청 → 확인창 "7일 안에 주인이 거절하지 않으면 {닉네임}님이 주인이 돼요" → owner\_claims 생성 → 주인에게 owner\_claim\_requested 푸시
- 요청 중에는 모든 멤버의 E1에 "{닉네임}님이 주인 맡기를 요청했어요 · {남은 일}일 남음" 표시, 다른 멤버는 추가 요청 불가
- 주인이 E1에 들어오면 상단 배너 "주인 맡기 요청이 있어요" + "계속 맡을게요"(거절, owner\_claim\_rejected) / "넘겨줄게요"(즉시 위임)
- OWNER\_CLAIM\_WAIT(7일) 동안 응답이 없으면 스케줄 작업이 위임 → owner\_transferred, 이전 주인은 멤버로 남음
- 요청자가 그 사이 나가면 요청은 expired, 주인이 접속만 해도 요청은 유지(명시적 거절만 취소)

**데이터**: diaries, diary\_members(muted), entry\_unlocks(기간 늘릴 때).

### E2 멤버 관리

**진입**: E1 멤버 행, C1 아바타 묶음, join\_requested·member\_joined 알림.

**배치**

1. 상단 바: 뒤로 + "멤버"
2. (주인만) "참여 요청 {N}" 섹션: 아바타, 닉네임, "{M월 D일} 요청", 이전에 나갔거나 내보낸 사람이면 보조 칩 "이전 멤버", 차단한 사람이면 보조 칩 "차단한 사용자", 버튼 "거절" / "승인"
3. "멤버 {N}/10" 목록(아바타 순서 규칙): 아바타, 닉네임, 주인 왕관, "{M월 D일} 참여"
4. (주인만) 각 멤버 우측 ⋯ → "내보내기"

**상태**

- 대기 요청 0개: 요청 섹션 숨김
- 인원 10명: 승인 버튼 비활성 + 섹션 위 안내 "자리가 꽉 찼어요"

**동작**

- 승인 → decide\_request(승인) → 요청자에게 join\_approved, 기존 멤버에게 member\_joined
- 거절 → decide\_request(거절) → 요청자에게 join\_rejected
- 차단한 사용자 승인 → 확인창 "차단을 풀고 승인할까요?" → 차단 해제 후 승인
- 내보내기 → 확인창 "{닉네임}님을 내보낼까요? {닉네임}님의 일기와 댓글이 모두 사라져요" → remove\_member → 당사자에게 member\_removed, 남은 멤버에게 member\_left

**엣지 케이스**

- 요청자가 그 사이 취소·계정 삭제·만료: 승인/거절 시 토스트 "취소된 요청이에요" + 목록 갱신
- 주인 두 기기에서 같은 요청 처리: 먼저 처리된 결과 적용, 나중 것은 "이미 처리된 요청이에요"
- 주인 자신에게는 ⋯ 메뉴 없음(나가기는 E3)
- 내보내기 실패: 삭제 처리 순서대로 트랜잭션 롤백, 토스트 후 멤버 유지
- 멤버(주인 아님)는 요청 섹션과 ⋯를 보지 못함

**데이터**: join\_requests, diary\_members, member\_history, blocks, decide\_request, remove\_member.

### E3 일기장 나가기

**진입**: E1 "일기장 나가기".

**배치** (역할별)

- 멤버: ① 제목 "일기장을 나갈까요?" ② 사라지는 것 목록 "내가 쓴 일기 {N}편과 사진, 내가 남긴 댓글 {N}개와 반응, 이 일기장의 열림 기록" ③ 안내 "다시 들어와도 지운 기록은 돌아오지 않아요" ④ 링크 "내 일기 사진 저장하기" ⑤ danger 버튼 "나가기"
- 주인(다른 멤버 있음): ① 제목 "주인은 이렇게 나갈 수 있어요" ② 선택 카드 "다른 멤버에게 맡기고 나가기" → 멤버 목록 라디오 선택 ③ 선택 카드 "일기장 삭제하기" → 안내 "모든 멤버의 일기, 사진, 댓글이 사라져요" + 일기장 이름 입력창 ④ danger 버튼 "나가기" / "삭제하기"
- 주인(혼자): 위임 카드 없이 삭제만

**상태**: 삭제는 입력한 이름이 정확히 같을 때만 버튼 활성. 처리 중 전체 덮개 "정리하는 중".

**동작**

- 멤버 나가기 → leave\_diary → B1(스택 초기화) + 토스트 "{일기장}에서 나왔어요". 남은 멤버에게 member\_left
- 위임 후 나가기 → leave\_diary(transfer\_to) → 새 주인에게 owner\_transferred, 남은 멤버에게 member\_left
- 삭제 → delete\_diary → 모든 멤버에게 diary\_deleted
- 사진 저장하기 → 내 일기 사진 원본을 기기 앨범 "공주일기"에 일괄 저장(진행률 표시)

**엣지 케이스**

- 위임 대상이 그 사이 나감: "선택한 멤버가 없어요" + 목록 갱신
- 처리 중 앱 종료·네트워크 끊김: 서버 함수는 끝까지 실행. 재실행 시 일기장이 없으면 B1에서 정상 처리된 것으로 보임
- 사진 저장 중 권한 거부: 저장 중단 + 설정 이동 안내
- 나간 뒤 재참여: B3에서 정상 요청 가능, 주인 화면에 "이전 멤버" 표시

**데이터**: leave\_diary, delete\_diary, member\_history, entry-photos.

## F·G. 알림과 설정

### F1 알림

**진입**: 하단 탭 알림.

**배치**

1. 상단: "알림" + 우측 "모두 읽음"
2. 묶음 헤더: 오늘 / 어제 / 이번 주 / 이전
3. 항목: 행동한 사람 아바타(없으면 일기장 커버 색 원), 문구(spec.md '알림 종류' 표), 시간, 안 읽음은 primarySoft 배경 + 왼쪽 점
4. join\_requested 항목은 주인에게 "거절" / "승인" 버튼을 바로 표시

**상태**

- 빈 상태: "아직 새 소식이 없어요"
- 대상이 사라진 항목(일기·댓글·일기장 삭제, 멤버 아님): 흐리게, snapshot 문구 유지

**동작**

- 항목 탭 → 읽음 처리 → 알림 종류 표의 "탭하면" 화면
- 모두 읽음 → 전체 read\_at 설정, 탭 배지 0
- 화면을 열면 보이는 항목을 자동 읽음 처리하지 않음(탭해야 읽음)
- NOTI\_RETENTION(30일) 지난 항목은 서버에서 삭제

**엣지 케이스**

- entry\_created인데 아직 잠김: C4로 이동(잠긴 카드 상태)
- reaction\_created 묶기: 같은 일기에 대한 안 읽은 리액션 알림은 1개로 합치고 actor\_count 증가, 최신 행동자 기준 문구 "{닉네임}님 외 {N}명이 일기에 반응했어요"
- 리액션 취소: 이미 만든 알림은 지우지 않음
- 사라진 대상 탭: 토스트 "사라진 글이에요" / "사라진 일기장이에요", 이동 없음
- 버튼으로 승인했는데 이미 처리됨: 토스트 "이미 처리된 요청이에요"
- 차단 관계인 사람이 만든 알림: 생성 자체를 안 함. 차단 전 만들어진 항목은 숨김
- 목록 페이지: 30개씩 무한 스크롤

**데이터**: notifications, decide\_request.

### G1 설정

**진입**: 하단 탭 설정, B1 아바타.

**배치**

1. 프로필 카드: 아바타, 닉네임, "편집"(→ A4 수정 모드)
2. 계정 섹션: "계정 연결" 행(연결됨이면 "구글로 연결됨" / "애플로 연결됨", 미연결이면 primary 경고 칩 "연결 안 됨")
3. 일기 섹션: 주 시작 요일(월 / 일), 화면 모드(시스템 / 라이트 / 다크)
4. 보안 섹션: 앱 잠금(→ G2, 켜짐/꺼짐 표시)
5. 알림 섹션: 알림 설정(→ G3)
6. 사용자 섹션: 차단 목록(→ G4 차단 목록)
7. 정보 섹션: 개인정보처리방침, 이용약관(인앱 브라우저), 문의하기(메일 앱, 앱 버전·기기 정보 자동 첨부), 앱 버전
8. 맨 아래 textSub 글씨 "계정 삭제"(→ G4 계정 삭제)

**상태**: 연결 상태에 따라 2번 표시가 바뀜.

**동작**

- 계정 연결(미연결일 때) → 바텀시트 "구글로 연결" / "애플로 연결"(iOS만) → 현재 익명 계정에 연결, 데이터 그대로 → 토스트 "계정이 연결되었어요"
- 계정 연결(연결됨일 때) → 정보만 표시, 해제 기능 없음
- 주 시작 요일 변경 → profiles.week\_start, C1·C2에 즉시 반영

**엣지 케이스**

- 연결하려는 구글/애플 계정이 이미 다른 공주일기 계정에 연결됨: 확인창 "이 계정에는 다른 공주일기가 있어요. 그 계정으로 바꾸면 지금 기기의 일기장은 볼 수 없어요" (취소 / 바꾸기). 바꾸면 현재 익명 계정 데이터는 그대로 남고 로그인만 전환
- 연결 도중 취소: 변화 없음
- 애플 "이메일 가리기": 정상 처리(이메일은 쓰지 않음)
- 안드로이드: 애플 연결 버튼을 표시하지 않음(구글만). iOS에서는 애플·구글 모두
- 앱 잠금이 켜진 상태에서 계정을 처음 연결: 이후부터 "잊었어요" 복구 가능

**데이터**: profiles, 인증(identity 연결).

### G2 앱 잠금 설정

**진입**: G1 앱 잠금, A2 "잊었어요" 재인증 성공(PIN 재설정으로 바로).

**배치**

1. 상단 바: 뒤로 + "앱 잠금"
2. 계정 미연결이면 경고 카드 "비밀번호를 잊으면 복구할 수 없어요" + "계정 연결하기"
3. "앱 잠금" 스위치
4. 켜져 있을 때만: "비밀번호 바꾸기", "잠금 시점" 즉시 / 1분 후 / 5분 후

**상태**: 스위치 꺼짐이면 4번 숨김.

**동작**

- 켜기 → (미연결이면 확인창 "복구할 수 없어요. 그래도 켤까요?" / "계정 먼저 연결하기") → PIN 입력 화면 → 확인 입력 → 해시 저장
- 끄기, 비밀번호 바꾸기 → 현재 PIN 확인 → 진행
- 잠금 시점 변경 → 기기 저장

**엣지 케이스**

- 확인 입력 불일치: "비밀번호가 달라요" 후 처음 입력부터
- 0000, 1234처럼 쉬운 PIN: 막지 않고 안내 "쉬운 비밀번호예요"
- 앱 안에서 시스템 화면(사진 선택, 공유 시트, 구글/애플 로그인, 인앱 브라우저)을 다녀올 때는 잠그지 않음
- 잠금 켜짐 동안: 최근 앱 화면에서 왕관 로고 화면으로 가림, 푸시 미리보기 가림
- 앱 삭제 후 재설치: 기기 저장소가 지워져 잠금은 꺼진 상태로 시작

**데이터**: 기기 secure storage만.

### G3 알림 설정

**진입**: G1 알림 설정.

**배치**

1. 상단 바: 뒤로 + "알림"
2. 시스템 권한이 꺼져 있으면 경고 카드 "휴대폰 설정에서 알림이 꺼져 있어요" + "설정 열기"
3. 스위치 4개: 새 일기 / 댓글 / 리액션 / 참여·멤버 소식
4. 저녁 리마인드 스위치 + 시간 선택(기본 21:00, 30분 단위)
5. 안내 "일기장마다 알림을 끄려면 일기장 설정에서 바꿀 수 있어요"

**상태**: 리마인드 꺼짐이면 시간 선택 숨김.

**동작**: 변경 즉시 user\_settings 저장(실패 시 스위치 원래대로 + 토스트).

**엣지 케이스**

- 시스템 권한 꺼짐: 스위치는 바꿀 수 있지만 경고 카드 유지
- 리마인드 발송 조건: 리마인드 시각에 오늘 안 쓴 함께 쓰기 일기장이 1개 이상(muted 일기장 제외). 여러 개여도 1회만
- 시간대 이동(여행): timezone은 앱 실행 시 갱신되므로 리마인드는 마지막으로 앱을 연 곳 기준
- 기기 여러 대: 모든 기기 토큰으로 발송, 발송 실패 토큰은 삭제

**데이터**: user\_settings, push\_tokens.

### G4 차단 목록 / 계정 삭제

두 화면이며 같은 ID를 쓴다.

**진입**: G1 차단 목록, G1 계정 삭제.

**배치 — 차단 목록**

1. 상단 바: 뒤로 + "차단 목록"
2. 목록: 아바타, 닉네임, "차단 해제" 버튼

**배치 — 계정 삭제**

1. 상단 바: 뒤로 + "계정 삭제"
2. 안내 "모든 일기, 사진, 댓글, 반응이 지워지고 되돌릴 수 없어요"
3. 내가 주인인 함께 쓰기 일기장 목록: 일기장마다 "맡기기(멤버 선택)" / "삭제" 선택
4. 확인 입력 "계정 삭제"라고 입력
5. danger 버튼 "계정 삭제"

**상태**

- 차단 목록 빈 상태: "차단한 사람이 없어요"
- 계정 삭제 버튼: 주인 일기장 모두 선택 완료 + 확인 문구 일치 시 활성

**동작**

- 차단 해제 → 확인창 → blocks 삭제 → 서로의 글 다시 보임
- 계정 삭제 → delete\_account → 기기 저장소 전체 초기화(PIN, 임시저장, 온보딩 기록) → A1부터 새로 시작

**엣지 케이스**

- 혼자 쓰기 일기장, 혼자 남은 함께 쓰기 일기장: 선택 없이 자동 삭제
- 맡기기 대상이 그 사이 나감: 삭제 시 오류 + 목록 갱신
- 처리 중 네트워크 끊김: 서버 작업 계속. 앱 재실행 시 세션이 없으면 A1부터
- 계정 연결한 사용자: 연결도 함께 삭제. 같은 구글/애플로 다시 시작하면 새 계정
- 차단한 사람이 일기장을 나가거나 계정을 삭제: 계정 삭제면 목록에서 사라짐, 나가기만 했으면 유지

**데이터**: blocks, delete\_account.
